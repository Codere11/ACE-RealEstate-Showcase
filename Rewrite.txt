================================================================================
WEBSOCKET — HOW IT WORKS
================================================================================

One WebSocket endpoint: /ws/{slug}

Flow:
  1. Client connects to ws://localhost:8000/ws/demo
  2. Server resolves org by slug, accepts connection
  3. Client sends {"type":"subscribe", "sid":"*"} or {"sid":"abc123"}
  4. Server adds client to in-memory set for that sid
  5. When an event is published (e.g., message.created):
     → Server iterates subscribers for that sid AND for "*"
     → Sends event JSON to each subscriber
  6. Client receives event, processes it (same handle() logic)
  7. On disconnect: remove from subscriber set

No threads. No polling. No SSE emitter lifecycle issues. No @Transactional.
Just: event published → loop over subscribers → websocket.send_json(event)

Event publishing function (called by all endpoints):
  async def publish_event(org_id, sid, event_type, payload):
      event = {"type": event_type, "sid": sid, "payload": payload}
      # Store in lead_events table (for replay on reconnect)
      db_event = LeadEvent(organization_id=org_id, sid=sid,
                           event_type=event_type, payload_json=payload)
      db.add(db_event); await db.commit()
      event["_seq"] = db_event.id
      
      # Send to WebSocket subscribers
      for ws in subscribers.get(sid, []):
          await ws.send_json(event)
      for ws in subscribers.get("*", []):
          await ws.send_json(event)

AUTH FLOW
================================================================================

  1. Angular login page → POST /login {username, password}
  2. Server verifies → returns {"token": "jwt..."}
  3. Angular stores in localStorage
  4. All authenticated requests include: Authorization: Bearer jwt...
  5. FastAPI dependency: get_current_user(token) → returns User or 401
  6. Admin endpoints check user.role == 'PLATFORM_ADMIN'

Public endpoints skip auth dependency.

================================================================================
CHAT FLOW
================================================================================

  POST /chat {sid, message, tenant_slug}:
    1. Resolve org by slug
    2. Get or create Lead (generate sid if not provided)
    3. Save user message: ConversationMessage(lead, USER, message)
    4. publish_event(org.id, lead.sid, "message.created", {role:"user", text:message})
    
    5. Check for active qualifier:
       qualifier = await db.query(Qualifier).filter_by(org_id=org.id, status='live').first()
       
    6. If qualifier:
         Call Python AI runtime (app.qualification.graph.run_qualification_graph)
         → returns {reply, profile, qualification_score, ...}
         Save assistant message
         publish_event(message.created, assistant)
         publish_event(lead.qualified, ...)
         Return {sid: lead.sid, reply: response.reply, ...}
       
    7. If no qualifier:
         Use survey flow (PublicChatService equivalent)
         Return next survey question as reply
    
    8. publish_event(lead.touched, {lastMessage, status, ...})

================================================================================
TAKEOVER FLOW
================================================================================

  POST /chat/staff {orgId, sid, text} (AUTHENTICATED):
    1. Verify user has access to org
    2. Find lead by org_id + sid
    3. Set lead.takeover_active = True, lead.status = HUMAN_TAKEOVER
    4. publish_event(lead.takeover.started, {sid, manager, takeover_active: True})
    5. Save staff message: ConversationMessage(lead, STAFF, text)
    6. publish_event(message.created, {role:"staff", text})
    7. publish_event(lead.touched, ...)
    8. Return {ok: true, takeover: {active: true, ...}}

  POST .../takeover/end (AUTHENTICATED):
    1. Set lead.takeover_active = False, lead.status = OPEN_CHAT
    2. publish_event(lead.takeover.ended, {sid, takeover_active: False})
